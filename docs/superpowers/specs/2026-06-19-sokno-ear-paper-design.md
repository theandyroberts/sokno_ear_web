## 1. Overview & scope

The South Knoxville Ear is a **weekly one-page web paper** for South Knoxville —
Sevier Avenue, the South Waterfront, Ijams, and the Urban Wilderness. It looks
like a beloved neighborhood newspaper that survived into the web era. Each week is
a single long scroll: full-width masthead, then every story inline. No "read more,"
no deep links, no pagination.

This spec covers two deliverables:

1. **The Paper** — a Next.js app that renders any weekly edition from a data file,
   with the live masthead, full inline scroll, working Tipline + Subscribe forms, a
   real audio briefing, per-week permalinks, and an archive page.
2. **Edition Zero** — the real **June 19–21, 2026** edition, authored (assisted) as
   the Paper's first data file, so launch day has real content.

**Deferred (sub-project 2 — the Newsroom):** turning assisted weekly production
into a repeatable/scheduled automated pipeline. We design that after one real
edition has been felt through by hand.

The design system already in the repo (`assets/The South Knoxville Ear — Design
System/`) is the **source of truth and is not redesigned.** Its tokens and React
components are reused verbatim; this project builds the data layer, rendering,
routing, forms, and deployment around them.

## 2. Editorial principles

- **Not a rumor/gossip site.** "Events And Rumors" is a backronym so the paper can
  be "The Ear" (E.A.R.). "Rumors" means **real local stories** — events, business
  openings, civic/zoning news — chosen to help neighbors **plan their weekend or
  know what's happening.**
- **No certainty labels.** The "Confirmed / Probably true / We'll see" system was
  auto-generated by the theme AI and is **removed**. Stories are vetted real before
  publishing; Andy reviews each week's lineup for now.
- **Community submissions are for future events and news** the neighborhood wants in
  the paper — never framed or labeled as "tips" or "rumors." The form invites people
  to tell The Ear what's coming up.
- **Voice:** neighborly, curious, lightly funny, useful, locally fluent, never mean.
  The warm "we hear things" brand voice stays — it signals being tuned in, not
  unverified gossip.
- **Casing:** headlines & rubrics ALL CAPS; body sentence case; labels condensed
  caps. **No emoji** — ornaments only (★ ◆ ❧).
- **Lexicon:** `content/LEXICON.md` governs pronunciation and usage for scripts and
  copy (e.g. **SoKno = "So-No"**, Sevier = "suh-VEER", Ijams = "EYE-jams"). It feeds
  the audio briefing TTS and grows every week.

## 4. Data model

One **Edition** = one published page. Stored as JSON, validated by a Zod schema in
`lib/schema.ts`.

```ts
Edition {
  slug: string            // "2026-06-20"
  volume: number
  number: number
  edition: string         // "Weekend Edition"
  date: string            // ISO; renders "Friday–Sunday, Jun 19–21, 2026"
  place: string           // "South Knoxville, TN"
  feature: Story          // top feature (renders via <Article>)
  scanner: StoryCard[]    // "Top Stories & Events" grid (3–6 cards)
  stories: Story[]        // full inline stories, in order
  sidebar: {
    audio?: AudioBriefing
    calendar: Event[]
    tipline?: Tipline
  }
}

Story {                   // -> <Article>
  id: string              // anchor target for nav + scanner cards
  label: string           // rubric, e.g. "Old Sevier" (ALL CAPS)
  labelColor?: "teal" | "rust"
  layout?: "imageLeft" | "imageRight" | "imageTop" | "banner" | "textOnly"
  image?: string          // assets/spots/* engraving or photo
  imageCaption?: string
  title: string           // sentence case, bold serif
  deck?: string           // 1–2 sentence why-it-matters
  facts?: { label: string; value: string }[]   // date/time/place/cost/source
  body: Block[]           // typed prose blocks (see below). NO certainty field.
}

Block =
  | { type: "paragraph"; text: RichText }   // RichText = limited inline: strong, em, link
  | { type: "subhead"; text: string }

StoryCard { label; image; title; blurb; cue; href; hot? }  // href = "#<Story.id>"
Event { month; day; title; meta; starred? }                // -> <CalendarItem>
AudioBriefing { title; duration; summary; src }            // -> <AudioBriefing>
Tipline { heading; body }                                  // -> <Tipline>
```

Component prop contracts live in each `.d.ts` in the design system; content fields
map to those props — no new props invented. The only model change from the original
brief: **`certainty` is dropped** and **`layout` is added**.

## 5. Story layout variants

To keep a long scroll from going monotonous, `Story.layout` selects a presentation:

- **Week 1:** implement `imageLeft` / `imageRight` and **alternate** them down the
  page (plus `imageTop` for the feature). This is enough to break monotony.
- **Fast-follow (not week-1 blocking):** `banner` (full-width lead image) and
  `textOnly` variants, plus per-story overrides.

Implementation: a thin `ArticleLayout` wrapper around the existing `<Article>` that
positions the engraving left/right/top without altering the component's styling.

## 6. Routes & pages

- `/` — renders the **latest** edition (newest slug).
- `/<slug>` — permalink to a specific week (editions never disappear).
- `/archive` — list of past editions. **Week 1:** intentionally empty, showing a
  centered epigraph in the display type:
  > *"There are far, far better things ahead than any we leave behind."* — C.S. Lewis
- In-page nav = anchor links to section ids (Events / Around the Neighborhood /
  Waterfront / Wilderness / Listen). No router, no "read more."

Footer carries the existing tagline + a **Past Issues / Archives** link.

## 7. Forms (working)

Both render using the design system's `Tipline` component styling and post to Next
route handlers; all submissions land in SQLite.

**Submit an Event / News — `POST /api/submit`** — this is the design system's
`Tipline` slot, **reframed**: it collects **upcoming events and news the community
wants in the paper** — *not* tips or rumors. Public copy is invitational and
event/news framed (e.g. heading "Got an event? Tell The Ear"), with no "tip" or
"rumor" language anywhere on it.
- `headline` — **required** (the event or news in one line)
- `details` (textarea) — **required**
- `url` — optional (link to more info / official page)
- `dates` — optional (when it happens — a date or range)
- `contact` — optional (name / email / phone, so Andy can follow up for details)
- Honeypot field + light rate-limit for spam.
- On submit: insert row into `submissions` table **and** email it to
  `andy@note15.com` (transport per §11).

**Subscribe — `POST /api/subscribe`**:
- `email` — required (+ honeypot).
- Insert into `subscribers` table (dedup on email). **Store-only in v1 — no
  Buttondown, no outbound send.** Future plan: export to a self-hosted **Listmonk**
  instance and send via **AWS SES**.

SQLite file lives outside the build dir (e.g. `/var/lib/soknoear/ear.db`) so deploys
don't clobber it. Schema migrations are simple `CREATE TABLE IF NOT EXISTS`.

- Output MP3 at `public/audio/<slug>.mp3`, wired into the existing `<AudioBriefing>`
  player (no third-party podcast widget).

## 9. Spot art

Each story leads with a **black-ink stipple engraving** ("story stamp"). Reuse the
existing `assets/spots/*` where they fit; generate new ones with the Higgsfield image
MCP using the `DESIGN_DIRECTION.md` §12 prompt formula (black ink linework, stipple
shading, cream paper, sparing teal/rust, subtle SoKno cue). Engravings are decorative
(`alt=""`); meaningful photos get real alt text.

## 11. Deployment

Target: Andy's **DigitalOcean VPS** — Ubuntu 24.04.3, Node v20.20.0, nginx 1.24.0,
certbot 2.9.0, PM2 v6. `ssh andy@143.244.188.235` (passwordless sudo configured).

Steps (Claude performs directly, mirroring existing sites like `note15.com`):
1. Create a **GitHub repo**; push the app.
2. On the VPS: clone, `npm ci`, `npm run build`, start the standalone server under
   **PM2** (named `soknoear`), proxied by nginx.
3. Write `/etc/nginx/sites-available/soknoear.com` (mirror an existing root-domain
   vhost), symlink to `sites-enabled`, `nginx -t`, reload.
4. **DNS gate:** `soknoear.com` currently resolves to `216.40.34.41` (registrar), not
   the VPS. Once the A-record points to `143.244.188.235`, run **certbot** for TLS.
5. **Email transport:** the VPS has **no MTA**, so submission emails send via the
   **Resend API** (`lib/mail.ts`) from the `send.note15.com` sending domain to
   `andy@note15.com`. `RESEND_API_KEY` is provided in `.env.local` (gitignored, set
   in the PM2 process env on the VPS). Submissions always persist to SQLite
   regardless of email success.

Weekly publish = commit new edition JSON + assets → on VPS `git pull && npm run build
&& pm2 restart soknoear`.

## 12. Edition Zero — content plan (June 19–21, 2026)

point; some came from an AI summary, so **each event is verified with live web
search** (Ijams calendar, Visit Knoxville, venue socials) before it runs. Anything

place/cost/source), body in voice. Alternating image left/right layout.
